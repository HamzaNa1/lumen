Home is assembled from the user's configured section slots. Each section obtains its own data from the server; permissions, playback history, library metadata, and user preferences determine which items qualify. The following separates section selection from item selection.

## Web client: choosing sections

The current web client's modern Home route still loads the legacy `hometab` controller, which gets the current user and calls `homeSections.loadSections`. That function fetches the user's views/libraries, resolves section preferences, creates the section containers in preference order, and dispatches a separate loader for each type. If no user views are returned, it displays the no-libraries message instead. [Home route](https://github.com/jellyfin/jellyfin-web/blob/6d2b5922a9069f1bafbde3a620c727bb9d34a6ac/src/apps/modern/routes/home.tsx#L66-L95), [HomeTab](https://github.com/jellyfin/jellyfin-web/blob/6d2b5922a9069f1bafbde3a620c727bb9d34a6ac/src/apps/legacy/controllers/hometab.js#L15-L39), [section loading](https://github.com/jellyfin/jellyfin-web/blob/6d2b5922a9069f1bafbde3a620c727bb9d34a6ac/src/components/homesections/homesections.js#L58-L107).

There are ten configurable slots, `homesection0` through `homesection9`. A missing preference uses the corresponding default. The defaults are **My Media → Continue Watching → Continue Listening → Continue Reading → Live TV → Next Up → Latest Media → three disabled slots**. An explicit `none` disables a slot. TV layout prepends My Media if the chosen slots contain neither library tiles nor library buttons. [defaults](https://github.com/jellyfin/jellyfin-web/blob/6d2b5922a9069f1bafbde3a620c727bb9d34a6ac/src/constants/homeSectionType.ts#L3-L29), [slot resolution](https://github.com/jellyfin/jellyfin-web/blob/6d2b5922a9069f1bafbde3a620c727bb9d34a6ac/src/components/homesections/homesections.js#L24-L55).

The normal home path enables horizontal overflow, so its request limits are:

| Section | Web request and display rule |
| --- | --- |
| My Media | Render the returned user views in their returned order as tiles or buttons. |
| Continue Watching / Listening / Reading | Separate resume queries with media type Video / Audio / Book, each limited to **12**. |
| Next Up | Request **24**, pass `enableResumable: false`, a last-activity cutoff (default **365 days**), and the user's rewatching setting (default **false**). |
| Latest Media | Expand one configured slot into a separate row per eligible user view, each limited to **16**, or **30** for music. Skip views in `LatestItemsExcludes` and the playlists, live TV, collections/boxsets, channels, and folders view types. |
| Live TV | Require `EnableLiveTvAccess` and at least one currently airing program; then request up to **24** airing programs through the recommended-programs API. |
| Active Recordings (optional) | Request up to **12** recordings with `isInProgress: true`. |

## Server rules

### Libraries / My Media

The server starts with the user's visible root folders, optionally groups compatible movie/TV libraries according to their preferences, and can include channels and Live TV when available to that user. Empty playlist/collection libraries are omitted. The API defaults `includeHidden` to false, so `MyMediaExcludes` removes hidden views from the response. Views follow the user's `OrderedViews` preference, with remaining views sorted by name. [View construction](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/Library/UserViewManager.cs#L45-L152), [API defaults](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Api/Controllers/UserViewsController.cs#L65-L95)

### Continue Watching / resumable media

The resume endpoint requests resumable, nonvirtual items of the requested media types, sorted by **last playback date, newest first**. A nonfolder item is resumable when the current user's saved `PlaybackPositionTicks` is greater than zero. With alternate versions, the query returns the most recently played version that still has progress. [Resume endpoint](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Api/Controllers/ItemsController.cs#L978-L999), [Resumable filter](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.TranslateQuery.cs#L562-L612)

Saving playback progress applies thresholds. For ordinary media with known runtime, defaults ignore progress before **5%**, clear progress and mark watched beyond **90%** (or within one second of the end), and disallow resume for media shorter than **300 seconds** once past the initial-progress threshold. Books/audiobooks have separate handling. These thresholds are configurable. [Defaults](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/MediaBrowser.Model/Configuration/ServerConfiguration.cs#L129-L145), [Progress rules](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/Library/UserDataManager.cs#L439-L497)

For a root-level resume request, library exclusions come from `LatestItemExcludes`, not `MyMediaExcludes`. Normal library access and parental/tag restrictions also apply. The API can additionally exclude currently playing sessions when requested. [Resume exclusions](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Api/Controllers/ItemsController.cs#L951-L997), [Access filtering](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.QueryBuilding.cs#L454-L476)

### Next Up

For the global request, the server first identifies series with an episode playback date on or after the requested cutoff, in the allowed libraries. Thus a never-started show does not automatically qualify merely because it was recently added. An explicit request for one `SeriesId` bypasses this global candidate selection. Root-level Next Up also respects `LatestItemExcludes`. [Series candidates](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/NextUpService.cs#L42-L69), [Parent and series selection](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/TV/TVSeriesManager.cs#L36-L107)

For each qualifying series, ordinary Next Up finds its **highest season/episode marked played**, then selects the first available unplayed episode after that position, in season/episode order. It does not backfill skipped earlier episodes. Missing/virtual episodes are excluded. A candidate series with no completed episode can start with its first unplayed episode. [Last watched position](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/NextUpService.cs#L93-L117), [Next episode selection](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/NextUpService.cs#L192-L247)

The resulting cards are ordered by the playback date of that selected last-watched episode (including its played alternate version), descending. If resumable episodes are disabled in the request and the chosen next episode already has progress, the server omits that series' result; it does not jump ahead another episode. Specials can be inserted using aired-order metadata when `DisplaySpecialsWithinSeasons` is enabled. Optional rewatching adds separate already-watched candidates. [Ordering and rewatching](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/TV/TVSeriesManager.cs#L117-L178), [Specials and resumable handling](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/TV/TVSeriesManager.cs#L181-L247)

### Latest media

Latest uses the stored **date added (`DateCreated`)**, not release date, popularity, or a relevance score. That date may come from the file's creation time, depending on server metadata configuration. Unplayed filtering follows `HidePlayedInLatest` when the request does not override it; this preference defaults true. Music libraries override the played filter. Virtual items are excluded. [Latest endpoint](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Api/Controllers/UserLibraryController.cs#L529-L569), [Preference default](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/MediaBrowser.Model/Configuration/UserConfiguration.cs#L16-L28), [Music and query filters](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/Library/UserViewManager.cs#L289-L388), [Date-added assignment](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Emby.Server.Implementations/Library/ResolverHelper.cs#L133-L154)

With grouping enabled (the API default), latest movies are deduplicated by presentation identity and ordered by date added; music returns albums ordered by each album's date added. Both use descending ID as a tie-breaker in this snapshot. [Grouped latest implementation](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.Querying.cs#L107-L255)

Latest TV chooses one representative per series-name group, sorted by its newest matching episode's date added. It considers episodes within **24 hours before that series' newest addition** (not necessarily the last 24 hours from today):

- Additions spanning multiple seasons show the **series**.
- Several additions within one season of a multiseason series show the **season**.
- Several additions within a single-season series show the **series**.
- Otherwise it shows the newest **episode**. A complete one-episode season also qualifies for container selection.

That explains why adding a batch of episodes can produce a show/season card while adding a single episode often produces an episode card. Restricted season/series containers fall back to an allowed episode. [Window and grouping](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.Querying.cs#L282-L366), [Container selection and access checks](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.Querying.cs#L402-L488), [Final ordering](https://github.com/jellyfin/jellyfin/blob/208c278b75abd897aefa1e1175126eac5e4dbfaa/Jellyfin.Server.Implementations/Item/BaseItemRepository.Querying.cs#L501-L539)

## Verification scope

These findings come from tracing both cloned repositories: the Home route, section dispatcher, settings, API request builders, server controllers, managers, and database queries. No Jellyfin server or fixture library was run. These are current master snapshots; installed releases or other clients may differ. No application code in hmedia was changed for this research.
